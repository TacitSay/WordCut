# 视频剪辑精度实测

> 日期：2026-10-27
> 目的：验证「按 EDL 删除区间剪视频」的两种实现路线的时间精度与性能
> 结论：**只采用精确模式（局部重编码），放弃流复制模式**

---

## 测试条件

| 项 | 值 |
|---|----|
| 源视频 | `F:\树林\心理\merged_video.mp4` 截取 600–720s 共 120 秒 |
| 编码 | H.264 / 1280×720 / 25fps，音频 AAC 44.1kHz 立体声 |
| 体积 | 4.2 MB |
| 删除区间 | 10–15s、40–43.5s、80–82s（共 3 段，合计 10.5s） |
| 预期输出时长 | 109.5s |
| 关键帧间隔 | 约 1s（实测：[0.042, 2.002, 7.002, 11.362, 12.962]…） |

## 实测结果

| 模式 | 实现 | 耗时 | 输出时长 | 偏差 | 重编码比例 |
|------|------|------|---------|------|-----------|
| fast | 全程 `-c copy` + 关键帧吸附 | 749 ms | 133.616 s | **+24.116 s** | 0% |
| precise | 剪辑点局部 `libx264` 重编码 | 4572 ms | 109.663 s | **+163 ms** | 14.6% |
| 合流 | `-c:v copy` + AAC 音轨 | — | 109.62 s | — | 视频流零损失 |

## 关键发现

### 1. 流复制模式的时间精度不可控

```bash
ffmpeg -ss 10.0 -t 5.0 -i src.mp4 -c copy out.mp4
```

在 `-c copy` 模式下，`-t` **按包（packet）边界截断，而非按时间戳**。H.264 的单个包可能跨越多个时间戳，
导致实际切出的内容显著多于 `-t` 指定时长。4 个片段累计多出 24.116 秒。

这不是实现 bug，是 **MP4/H.264 容器的固有限制**：不重编码就无法在任意时间点精确切割。

### 2. 精确模式的残差来自音频编码器帧对齐

`libx264` 在帧级精确（25fps 下 40ms/帧），但 AAC 编码器以 1024 样本为帧单位
（44.1kHz 下约 23ms）。多个剪辑点叠加后残差约 163ms，**在听感与视觉上不可察觉**。

### 3. 性能可接受

4.5 秒处理 2 分钟视频 = 重编码约 14.6% 的内容。处理 2 小时视频时，耗时**主要取决于剪辑点数量**
（每个剪辑点重编码一个 GOP）而非总时长。

## 决策

**只实现 precise 模式。** `CUT_MODE_FAST` 常量保留但内部重定向到 precise，
并在代码注释中记录本实测结论。

放弃 fast 模式的理由：

1. 时间轴必须精确——本课题的核心是词级时间戳（180–300ms），视频若偏差 24s，字幕与音频全部错位；
2. 音频来自 `edl_render`，是精确的，视频必须与之严格对齐；
3. 「用静帧铺盖画面」只能掩盖解码花屏，**不能修正时长错误**。

## 论文价值

这是一条**可量化的工程权衡结论**：

> 在 MP4/H.264 素材上，流复制剪辑的时间误差可达删除量的 230%（删 10.5s，偏差 24.1s），
> 无法用于需要帧级对齐的场景；采用剪辑点局部重编码后，误差降至 163ms，
> 代价是约 15% 的内容重编码。

可作为第 6 章「系统测试与结果分析」中的一组对照实验。
