# 毕设记录体系

> 题目：**基于词级对齐的播客访谈文本驱动剪辑系统设计与实现**
> English: Design and Implementation of a Text-Driven Editing System for Podcast and Interview Audio Based on Word-Level Alignment
> 建立日期：2026-10-22

---

## 0. 课题定位（先钉死，避免后面跑偏）

| 项 | 内容 |
|---|---|
| **研究问题** | 在只有句子级时间戳的语音识别结果之上，如何把"文本删除意图"精确映射为"音频样本级剪辑"，并保证拼接无爆音、字幕与音频严格一致 |
| **核心方法** | 词级/字级时间对齐 + 编辑决策列表(EDL) + 剪辑点声学精修 |
| **产物** | 本地 Web 工具：音频 → 转写 → 文本删改 → 导出成品音频 + 重定时 SRT + EDL |
| **明确排除** | 视频处理、TTS 语音合成、翻译、多用户/登录、云部署 |
| **复杂度来源** | 不是"会调 whisper"，而是：①对齐精度提升 ②边界声学约束求解 ③长音频资源约束 ④编辑状态一致性 |

**一句话自检**：任何功能如果不能回答"这解决了哪个约束冲突、怎么用数据证明"，就不要写进论文。

## 1. 论文结构（7 章）

标准本科软件工程毕设结构，每章都必须有可追溯的证据，不能只有文字。

| 章节 | 核心内容 | 必须有的证据/数据 |
|---|---|---|
| **第1章 绪论** | 研究背景与意义；国内外研究现状；研究内容与目标；论文组织结构 | 竞品对比表（国外商业软件 + 剪映/PR/Audacity）；文献清单≥20篇（近5年）；场景痛点量化（人工剪辑耗时实测） |

## 2. 记录体系（目录结构）

```
毕设/
├─ docs/
│  ├─ 记录.md            ← 本文件（总纲）
│  ├─ 实验日志.md        ← 每次实验一条，按 E001/E002 编号
│  ├─ 决策记录.md        ← ADR，每个技术选型一条
│  ├─ 数据集说明.md      ← 音频来源、授权、标注规范、标注人
│  ├─ AI使用登记.md      ← 学院硬性要求，逐次登记
│  └─ 问题记录.md        ← 现象/根因/解法/验证
├─ experiments/
│  └─ E001-对齐精度/
│     ├─ params.json     ← 参数快照
│     ├─ output/         ← 原始输出（json/csv/wav）
│     ├─ metrics.csv     ← 指标汇总
│     ├─ 图表/           ← 论文用图
│     └─ 结论.md
├─ figures/              ← 论文插图源文件（可编辑）
├─ data/
│  ├─ audio/             ← 被测音频 + 来源授权说明
│  └─ annotation/        ← 人工标注（原始 + 复核）
└─ src/                  ← 代码（git 管理）
```

### 记录纪律（三条硬规则）

1. **没记 = 没做**。实验做完当场记录，隔天补记的数据不可信。
2. **结论必须含数字**。"效果较好"无效；"MAE 从 214ms 降到 87ms"有效。
3. **每个数字可追溯**。论文里任一数字，都要能指到 `experiments/EXxx/metrics.csv` 的具体行。

## 3. 必须记录的点（12 类）

### R1 环境快照（每次阶段切换记一次）

- Python / torch / faster-whisper / ffmpeg / CUDA 驱动 版本
- GPU 型号、显存、CPU、内存
- 记录位置：`docs/实验日志.md` 顶部

**原因**：论文第 5、6 章必须写"测试环境"，且复现性要求版本固定。

### R2 数据集与标注（一次性建好，持续扩充）

| 必记项 | 说明 |
|---|---|
| 音频来源 | 自录 / 公开授权播客 / CC 协议；**必须能说明合法性** |
| 基本信息 | 时长、采样率、声道、语言、说话人数、录音环境 |
| 标注规范 | 标注粒度（字/词）、边界定义（起点取能量上升沿？）、容差 |
| 标注人 | 谁标的；建议双人标注，记录一致性 |
| 标注文件 | 原始 + 复核版，不能覆盖 |

**建议规模**：中文 3–5 段真实播客（每段 5–15 分钟），标注 ≥200 个边界；英文 1–2 段作对照。

### R3 对齐精度实验（最高优先级）

每次实验记录：

- 参数：模型（tiny/base/small/medium）、`word_timestamps`、VAD 开关、beam_size、language
- 输出：每个边界的"预测时间 vs 人工标注时间"
- 指标：MAE、中位数误差、P90 误差、>200ms 的异常占比
- 对照：**句子级 / 字级 / 强制对齐** 三组必须同数据集对比

**这是整个课题的地基，也是第 3 章的核心实验。**

### R4 剪辑点实验

| 必记项 | 说明 |
|---|---|
| 剪辑点确定策略 | 词边界直切 / 吞并静音一半 / 能量谷底吸附 / 过零对齐 / 组合 |
| 拼接方式 | 硬切 / 等功率 crossfade（记时长，如 8ms、15ms） |
| 爆音检测 | 阈值定义（样本一阶差分阈值）、检出计数 |
| 主观验证 | 自己听 + 至少 2 人盲听评分（1–5 分） |
| 图表 | 拼接点波形放大图、频谱图（论文必用） |

**必做对照**：硬切 vs 过零 vs 过零+crossfade，三组爆音率对比。

### R5 长音频性能实验

| 必记项 | 说明 |
|---|---|
| 输入规模 | 10min / 30min / 60min / 120min |
| 策略 | 全量 vs 分段（分块时长 5/10/15min） |
| 指标 | 总耗时、峰值显存（`nvidia-smi` 定时采样）、峰值内存、CPU 占用 |
| 质量影响 | 分段边界处的对齐错位（ms）、跨块词被切断次数 |

**显存采样必须留原始日志**，论文要画曲线。

### R6 一致性实验（EDL 正确性）

- EDL 回放重建音频 vs 直接导出音频：逐样本 diff，输出最大差值、不一致样本数
- 编辑 2 次/5 次/10 次后，时间映射表的累积误差
- 撤销重做后状态哈希是否回到原值

**这一项证明"非破坏性编辑模型"是对的，是第 6 章的独立性章节。**

### R7 决策记录 ADR（答辩可辩护性的核心）

每个技术选型一条，格式见第 5 节。至少覆盖：

- 为何 whisper 而非其他 ASR
- 为何词级 DTW 而非直接上强制对齐（或反之）
- 为何 EDL 而非直接改文件
- 为何 PCM 拼接而非 ffmpeg filter_complex
- 为何本地 Web 而非桌面 exe
- 为何排除 TTS/翻译/视频

### R8 问题记录

格式：现象 → 环境 → 根因 → 尝试过的方案（含失败）→ 最终解法 → 验证方式。

**失败方案必须记**，答辩问"你试过 X 吗"时有据可答。

### R9 AI 使用登记（学院硬性要求，缺了有风险）

按学院方案第 10 条：如实登记工具类型、使用场景、生成内容，完整留存原始素材，逐一核验。

| 必记项 | 说明 |
|---|---|
| 时间 | 具体日期 |
| 工具 | 名称/版本 |
| 场景 | 代码生成 / 查文档 / 翻译 / 调试 / 文字润色 |
| 生成内容 | 摘要或文件路径 |
| **核验方式** | 你怎么验证它是对的（跑通？对照文档？单测？） |
| 是否采纳 | 采纳 / 部分采纳 / 否决（及原因） |

**红线**：方案设计、核心算法代码、实验数据分析必须自己做；AI 只做辅助。

### R10 版本与提交

- 每个可运行节点打 tag（v0.1 / v0.2 …）
- 论文写实现时要能引用"v0.6 中的 XX 模块"
- 提交信息写清"做了什么 + 为什么"

### R11 截图证据

- 每个功能界面至少 1 张（干净数据、可读）
- 每个实验结果至少 1 张图（波形/曲线/对比表）
- 命名规范：`fig-章节号-序号-描述.png`（如 `fig-6-3-爆音率对比.png`）

### R12 场景与竞品调研

- 播客/访谈创作者的真实工作流（问 3–5 人，记原话）
- 人工剪辑耗时实测（自己用 PR/剪映剪 10 分钟音频，计时）
- 竞品功能矩阵：国外商业软件、剪映、PR、Audacity、Descript
- **务必记对方"缺什么"**——这是选题立论依据

## 7. 图表与数据的可追溯规则

1. **图必有源**：每张图对应 `experiments/EXxx/图表/` 下的源文件，论文不放"手工画的示意图冒充数据图"。
2. **表必有口径**：每个指标写清怎么算的（公式或脚本路径）。
3. **对照必有基线**：任何"提升"都要有对照组，禁止只报绝对值。
4. **异常必须保留**：跑失败的数据不删，放 `output/rejected/`，答辩可能用得上。

| 阶段 | 完成标志 | 关键产出 |

## 9. 开题前必须能回答的 5 个问题

1. 你的对齐精度具体是多少毫秒？和句子级差多少？
2. 剪辑点为什么切在那里？爆音率降到多少？
3. 1 小时音频跑多久、占多少显存？分段后改善多少？
4. 编辑 10 次之后，字幕和音频还对得上吗？怎么证明？
5. 和剪映/该商业软件比，你多解决了什么？

**答不上就别开题。**
