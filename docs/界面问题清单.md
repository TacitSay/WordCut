## 设计讨论记录

### L2 的争议点

"滚动文档音频条始终在中间上面"有两种读法：

- **A：吸顶**（推荐）——波形固定在视口顶部，文本在下方滚动。播放头随时间前进自动滚动到对应词。
- **B：视口跟随**——波形跟着当前播放词滚动，模拟"音频跟随文字"。

A 实现简单且稳定；B 更贴近"跟随"但容易造成视觉疲劳。**先做 A**，B 作为可选增强。

> 2026-10-30 补记：A 已完成（波形 sticky）。"播放头自动滚动到对应词"按 A 的思路做在**文本侧**——
> 当前正在播放的词高亮为琥珀色并平滑滚入视口中央（`TextEditor.vue` 的 `activeIndex` 监听）。
> 词与词之间的停顿不高亮，避免"没人说话时还在闪"。

### I2 分段的三种依据

1. 按 faster-whisper 的 `seg`（句子级切分，最稳）
2. 按标点（。？！，；）
3. 按时间间隔（> 0.6s 视为新段）

建议 1 + 3 组合：`seg` 变化或间隔 > 0.6s 就换段。当前实现见 `src/segmenter.py`（规则分段；
`Segmenter` 接口已留，替换实现即可升级为语义分段，即推后项 P6）。

## 第二轮反馈（2026-10-30 试用后提出）—— 全部已处理

| # | 反馈原话 | 判断 | 处理 |
|---|---------|------|------|
| R1 | "点击应用参数 峰值并不会改变（导出有效果）" | **不是后端 bug**（实测 normalize→-1.00、gain -6→-6.29 都正确）。是面板口径问题：未转写时没有「成片」数据，用户只能看到「源」指标，而源素材本来就不受参数影响 | 已改：`/audio-info` 未转写时也算「源 + 当前参数」的成片指标；面板拆成「源（只读）」与「成片（当前参数）」两组，并回显「统计所用参数」；保存后状态栏显示 `成片峰值 -0.29 → -1.00 dBFS` |
| R2 | "鼠标拖拽选择大片文字 可以加" | 需求合理 | 已加：Token 上按下 → 拖动跨词 → 松开成选区；拖动中禁用原生文字选择；未拖动则保持原有点击语义（点击红字恢复 / 点击定位播放头） |
| R3 | "有删减音频立马可以听到（及时反馈）" | 需求合理，且这正是"文本驱动剪辑"该有的手感 | 已加：`POST /audition` 按当前编辑状态渲染后回传关注点前后 1.2s（经 TimeMap 换算到目标时间轴），前端删除/恢复后自动播放；`播放` 菜单可关；与主播放器互斥。实测：删除后片段 hash 变化、恢复后 hash 回到原值（缓存键含删除状态与参数） |
| R4 | "关键词搜索（加）" | 需求合理 | 已加：`Ctrl+F` 打开搜索栏，支持**跨 Token** 匹配（中文常被切成单字，"我们"可能横跨两个 Token）；`Enter`/`↑↓` 跳转并选中命中区间、播放头跟随；**「删除全部匹配」**一键清口癖/重复词 |
