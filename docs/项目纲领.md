# 项目纲领 —— 大方向与大体结构

> 题目：**基于词级对齐的播客访谈文本驱动剪辑系统设计与实现**
> 本文件是最高层级的锚点。任何开发、任何文档、任何 AI 生成代码，都以本文件为准；与本文冲突的，以本文为最终依据。
> 建立：2026-10-25

---

# 第一部分 · 大方向

## 1. 一句话定位

> **一款以"文本"为主界面的播客/访谈剪辑工具**——用户读文字、删文字，系统自动映射成音频剪辑，产出成品音频 + 字幕。

不是"音频编辑器"，不是"语音转写工具"，更不是 AU 的替代品。

## 2. 核心差异（答辩立论点）

| 对比对象 | 对方怎么做 | 我们怎么做 |
|---------|-----------|-----------|
| AU / 剪映 / PR | 时间轴驱动，人听、找、拖 | **文本驱动**，人只读和删 |
| voice-pro / 转录工具 | 转写只到"字幕"就停 | 转写只是**输入**，终点是**剪辑成片** |
| 通用音频编辑器 | 效果器堆砌（全是常用方法） | 聚焦"文本→剪辑"这一件事做深 |

**一句话**：别人把"转文字"当终点，我们把"转文字"当起点。

## 3. 三个技术核心（深度所在）

| # | 核心 | 说明 | 为什么"超越常用方法" |
|---|------|------|---------------------|
| 1 | **词级/字级时间对齐** | 中文切成单字级 token（已验证：单字 81%） | whisper 只给句子级，词级对齐+异常边界修正是自研 |
| 2 | **文本删除 → 剪辑映射** | EDL 决策模型 + 剪辑点声学精修 | 语义边界与声学约束的联合求解 |
| 3 | **可扩展插件架构** | 功能大类 + 可插拔工具 | 稳定核心 + 接口层扩展，非硬编码 |

## 4. 功能边界（四个层级）

### P0 核心（必做）
文本编辑器 + 波形联动、词级对齐、EDL + 剪辑点精修、音频导入导出(wav/mp3/m4a)、撤销重做、项目保存/加载

### P1 剪辑必需（该带）
播放控制 + 波形视图、试听(光标跟随/选区播放)、静音段检测批量删除(VAD)、淡入淡出、音量标准化/增益/静音、音频信息统计

### P2 克制（只做简单版）
降噪（频谱门限/afftdn，不追求效果）；不做 EQ/压缩/混响效果链

### P3 明确排除
多轨混音、效果器链、MIDI、视频编辑、云协作、多用户/登录

### 预留（架构上留位，不承诺实现）
- **翻译节点**（本地 NLLB，字幕的自然延伸）
- **语音合成 TTS**（插件形式预留，工程顺利才做）

## 5. 明确的产品规则（写进需求，答辩会问）

1. **编辑分两类**：删除 → 映射到音频；插入 → 仅影响字幕（除非接 TTS）
2. **源文件只读**：剪辑永远通过 EDL 生成副本，禁止原地改源文件
3. **时间戳一律用秒**（float），禁止混用毫秒

# 第二部分 · 大体结构

## 6. 系统架构（分层）

```
┌─────────────────────────────────────────┐
│           前端 Vue3（单页应用）            │
│  菜单栏 │ 文本编辑区 │ 波形视图 │ 参数面板  │
│         │           │          │ 插件市场  │
└──────────────┬──────────────────────────┘
               │ HTTP / WebSocket（进度推送）
┌──────────────▼──────────────────────────┐
│         后端 FastAPI（核心服务）           │
│  ┌────────────────────────────────────┐ │
│  │        插件系统（挂载点/注册表）      │ │
│  │  菜单挂载 │ 面板挂载 │ 变体替换       │ │
│  └───┬──────────┬──────────┬───────────┘ │
│      ▼          ▼          ▼             │
│  [对齐模块] [剪辑模块] [音频处理模块]      │
│      │          │          │             │
│      └──────────┴──────────┘             │
│                ▼                         │
│    核心数据层：Token / EDL / TimeMap      │
│                ▼                         │
│    引擎：faster-whisper / ffmpeg / VAD    │
└──────────────┬──────────────────────────┘
               │
        SQLite（项目/任务/历史）
```

## 7. 模块划分

| 模块 | 职责 | 依赖引擎 |
|------|------|---------|
| 对齐模块 | 词级时间戳生成、异常边界修正 | faster-whisper |
| 剪辑模块 | 文本删除→EDL→剪辑点精修→拼接 | ffmpeg / numpy |
| 音频处理模块 | 静音检测、淡入淡出、增益、降噪 | ffmpeg / VAD |
| 核心数据层 | Token/EDL/TimeMap 模型 + 时间映射 | 无（纯逻辑） |
| 插件系统 | 挂载点管理、插件注册、schema→表单 | 无（纯逻辑） |
| 前端 | 编辑器、波形、播放器、插件市场 | WaveSurfer.js |

## 8. 核心数据模型（单一事实源）

| 实体 | 字段 | 说明 |
|------|------|------|
| **Token** | id / text / start / end / is_deleted / confidence | 最小可剪辑单元（中文=单字，英文=词） |
| **DeleteSpan** | start / end / token_id / cause | 一次删除对应的音频区间，cause ∈ {word, pause, repeat} |
| **EDL** | source / sample_rate / deletes[] | 编辑决策列表，非破坏性 |
| **TimeMap** | 分段线性映射表 | 源时间 ↔ 目标时间 双向可算 |

**不变量**（不可破坏，落到单元测试）：
1. 源文件只读
2. 时间戳单位统一为秒
3. EDL 可逆：回放结果 == 导出结果（样本级一致）
4. token.id 一旦生成绝不重排

## 9. 技术栈

| 层 | 选型 | 版本锚点 |
|----|------|---------|
| 前端 | Vue3 + WaveSurfer.js | — |
| 后端 | FastAPI | 0.139.x |
| 对齐 | faster-whisper + ctranslate2 | **ctranslate2 必须 4.4.0**（4.8.3 本机崩溃） |
| 剪辑/音频 | ffmpeg + numpy + soundfile | ffmpeg full build |
| VAD | Silero VAD 或 webrtcvad | 待验证 |
| 数据库 | SQLite（SQLAlchemy 抽象，可切 MySQL） | — |
| 部署 | 单进程（Vue build 静态文件由 FastAPI 托管） | — |

## 10. 插件扩展模型（借鉴 IDE/PR，非 ComfyUI 节点）

插件三种挂载方式：
1. **挂到已有大项下**（新菜单条目）
2. **成为已有条目的算法变体**（子菜单，如 afftdn 降噪）
3. **新开大项**（新顶级菜单 + 独立面板）

插件四种形态：command（命令）/ variant（变体）/ panel（面板）/ view（视图扩展）

**原则**：插件只接稳定接口，不能改核心状态机（EDL/TimeMap/撤销栈）。

```
  ↓
M5 插件系统：验证"新增一个插件 = 一个文件 + 界面自动出现"
  ↓
M6 完整评估：六类实验数据齐全
```
